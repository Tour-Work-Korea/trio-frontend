# 한·영 반응형 UI 구현 기준

한국어 화면은 기존 레이아웃을 기준으로 유지하고, 영어처럼 문장이 길어지는 언어에만 필요한 적응 동작을 적용한다.

## 공통 원칙

- 버튼, 헤더, 하단 탭, 칩, 모달, 빈 상태는 기존 공통 컴포넌트를 먼저 사용한다.
- 번역 문구를 담는 영역에는 고정 `width`보다 `flex`, `minWidth: 0`, `maxWidth`, 가로 여백을 사용한다.
- 아이콘과 이미지 크기는 고정할 수 있지만, 번역 문구를 담는 컨테이너에는 고정 높이를 새로 추가하지 않는다.
- 서버가 내려주는 카테고리명과 사용자 작성 콘텐츠는 번역하지 않는다. 길이가 긴 경우 가로 스크롤 또는 콘텐츠용 말줄임 규칙을 사용한다.
- 한국어에 영어용 `numberOfLines`, 글자 축소, 추가 줄바꿈을 강제로 적용하지 않는다.

## 텍스트 용도별 규칙

`AdaptiveText`의 `variant`를 문구의 역할에 맞춰 사용한다.

| 용도           | variant      | 영어 동작                         |
| -------------- | ------------ | --------------------------------- |
| 짧은 단일 값   | `singleLine` | 한 줄, 필요한 경우 축소           |
| 주요 버튼      | `button`     | 최대 두 줄, 필요한 경우 축소      |
| 화면/모달 헤더 | `header`     | 최대 두 줄, 가운데 정렬 영역 보존 |
| 하단/상단 탭   | `tab`        | 한 줄, 필요한 경우 축소           |
| 필터 칩        | `chip`       | 한 줄, 칩은 가로 스크롤 허용      |
| 섹션 제목      | `title`      | 최대 두 줄                        |
| 설명/안내      | `body`       | 자연스러운 줄바꿈                 |

사용자 작성 제목·본문이나 서버 콘텐츠는 제품 정책에 맞는 기존 말줄임을 유지한다. 번역된 고정 UI 문구를 사용자 콘텐츠와 같은 방식으로 무조건 자르지 않는다.

## 새 화면 체크리스트

1. 320~375pt 폭에서 한국어와 영어를 각각 확인한다.
2. 한국어 화면의 위치, 높이, 글자 크기가 변경되지 않았는지 비교한다.
3. 영어 버튼·헤더·탭이 서로 겹치거나 화면 밖으로 나가지 않는지 확인한다.
4. 긴 칩 목록은 가로 스크롤이 가능하고 선택 항목이 온전히 보이는지 확인한다.
5. 접근성 라벨과 모달을 포함해 언어 전환 즉시 현재 화면이 갱신되는지 확인한다.
6. 결과 화면은 `npm run test:i18n:capture -- <ko|en> <screen-name> [device-id]`로 캡처한다.

캡처 결과는 `.i18n-screenshots/`에 저장되며 로컬 검수 자료이므로 Git에는 포함하지 않는다.

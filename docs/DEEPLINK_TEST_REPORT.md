# 딥링크 검증 기록

검증일: 2026-11-08 (한국 시간)

## 범위

게하·파티 공유 HTTPS 주소, 앱의 `ddakji://` 상세 링크, 웹 앱/웹 선택창,
앱 실행 실패 시 스토어 이동, 잘못된 상세 ID, 한국어·영어 표시를 검증한다.
앱과 웹은 개발 API(`https://dev.ddakji.kr/api/v1`)를 사용한다.
예약·결제·게시·좋아요·참여·메시지 전송 등 서버 데이터 변경은 수행하지 않는다.

## iOS

- 기기: iPhone 17 Pro 시뮬레이터, iOS 26.4.
- 기존 Metro 8081 서버 재사용.
- `ddakji://guesthouse/14`: 앱 실행 중 / 종료 후 모두 ‘게딱지’ 상세 도착 확인.
- 게하 공유 버튼: `https://ddakji.kr/guesthouses/14?shared=1` 복사 확인.
- `ddakji://party/1804`: 앱 실행 중 / 종료 후 ‘돌고래 보러 가요🐬’ 상세 도착 확인.
- 파티 공유 버튼: `https://ddakji.kr/contents/1804?shared=1` 복사 확인.
- `ddakji://party/detail?partyId=1804`: 정상 상세 도착 확인.
- `ddakji://party/detail?id=1807`: ‘두개’ 상세 도착 확인.
- `ddakji://employ/21`: ‘테스트 공고2’ 상세 도착 확인.
- `ddakji://companion/15`: 동행 ‘테스트’ 상세 도착 확인.
- 존재하지 않는 게하 ID 1: 최초 검증에서 무한 로딩 발견. 오류 안내·재시도·홈 이동 추가 후 확인.
- 존재하지 않는 파티 ID 999999999: 오류 안내, 재시도, 정상 링크로 복귀 확인.
- 정상 게하에서 없는 게하 링크로 연속 이동: 이전 상세가 남지 않고 오류 화면 표시 확인.
- 예약 링크의 존재하지 않는 ID: 앱이 종료되지 않고 예약 목록으로 복귀. 유효한 예약 영수증 도착 검증을 대신하지 않는다.
- `ddakji://chat/1`: 접근 가능한 채팅방을 확보하지 못했으므로 정상 채팅 도착은 미검증.
- 개발 중 Hook 추가에 따른 Fast Refresh 오류·빈 화면이 있어 전체 재로드 후 재검증했다.

- 기존 설치본이 `workaway://`만 처리하여 현재 코드로 재빌드·교체 진행.
- 네이티브 빌드 및 실제 화면 검증: 진행 중.

## 공통 자동 검증

- `WebOpenApp.test.js`: 12개 통과.
- iOS/Android 각각 팝업 허용/차단 상황에서 올바른 스토어 이동 확인.
- 앱 실행으로 문서가 숨겨졌다 돌아오는 경우 설치 페이지 이동이 취소되는지 확인.
- pagehide 발생 시 설치 페이지 이동이 취소되는지 확인.
- 한국어·영어 리소스: 1780개 키 일치 검증 통과.
- 변경된 JavaScript의 JSX 구문 파싱 확인.

## 웹

앱 확인 후 기존 5173 서버가 없으면 시작하고, 테스트 후 에이전트가 연 탭과 서버를 종료한다.
웹 실제 브라우저 검증: 진행 전.

## 배포 관련 한계

이번 흐름은 웹 선택창에서 커스텀 스킴으로 앱 실행을 시도한다.
앱 설치 여부를 브라우저에서 확정 판별하는 방식은 아니며 메신저·브라우저 정책의 영향을 받는다.
HTTPS 주소를 OS가 곧바로 앱으로 여는 Universal Links / Android App Links는 활성화하지 않았다.
Play 앱 서명 SHA-256 파일은 준비됐지만 운영 도메인 인증 및 스토어 서명 실기기 검증은 별도이다.
본 기록은 전체 서비스나 결제 기능의 배포 승인을 의미하지 않는다.

### 최종 Safari 실제 결과 및 정리

- 현재 탭 방식에서도 설치 앱의 게하 상세로 이동은 확인했다.
- 그러나 Safari의 네이티브 ‘앱 열기’ 확인창에서 수 초 대기한 뒤 열고 Safari로 돌아오면 ‘주소가 올바르지 않아 페이지를 열 수 없음’ 알림이 재현된다. 기존 타이머 보완과 현재 탭 전환만으로 실제 충돌 해결을 확인하지 못했다. 자동 검증 통과를 이 실제 흐름의 통과로 해석하면 안 된다.
- 따라서 iOS 모바일 웹의 설치 앱 전환/자동 스토어 이동은 최종 통과 처리하지 않는다. 확정적인 설치 여부 분기는 브라우저 타이머 방식의 한계가 있으며, 운영 도메인과 앱의 Universal Links/App Links 설정·배포를 함께 검토해야 한다.
- 이번 변경으로 운영 배포 완료 또는 즉시 배포 안전성을 보증하지 않는다. 예약/채팅의 유효한 인증 데이터 링크도 여전히 별도 검증 대상이다.
- 직접 연 Safari 탭은 모두 닫고 기존 사용자 탭 4개는 유지했다. IAB 테스트 탭 종료 및 뷰포트 복원, Android Chrome 테스트 창 종료, 5173 포트 전달 제거와 직접 시작한 웹 서버 종료를 완료했다. 사용자 에뮬레이터와 기존 Metro 서버는 유지했다.

## 2026-11-08 Apple 설정 완료 확인 후 구성 반영

사용자가 Apple Developer Associated Domains 설정 완료를 확인하여 iOS capability/
entitlement/NSUserActivity 전달, 운영 AASA, Android HTTPS autoVerify 필터,
웹 CI의 두 인증 파일 JSON 업로드를 추가했다. 구체적인 배포 순서와 환경 제약은
APP_LINKS.md 참조. 이전 절의 ‘Universal Links 미활성화’는 이 설정 추가 전의
기록이며, 이번에는 저장소의 연결 구성을 추가했지만 실제 배포/도메인 인증
성공을 확인한 것은 아니다. 테스트·빌드는 이번 요청에서 새로 실행하지 않았다.
고정 사용자 문구/번역 키 추가·변경 없음. 서버/사용자 콘텐츠 원문 유지.

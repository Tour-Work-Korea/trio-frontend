## 발견 및 수정

- 문의 건수: management summary.inquiryCount는 문의 중 상태만 집계하여, 요청·거절 후 문의 이력이 있는데 0명으로 보였습니다. 관리 내역 전체 페이지를 조회해 대화 건수를 별도로 계산하도록 수정했습니다. 관리 화면의 문의 중 지표는 원래 상태별 집계를 유지합니다.
- 모집 관리에서 수락·거절을 다시 제공해 웹 채팅이 막혀도 참여 요청을 처리할 수 있게 했습니다. 기존 API·기존 문구를 재사용했습니다.
- 사용자 ID가 없는 프로필 세션에서 본인 표시와 신고 대상 제외를 보완했습니다. 확인 가능한 ID 및 본인 이메일을 사용하며, 본인 식별 수단이 없는 단체방 참여자 세션에서는 자기 자신을 잘못 신고하지 않도록 작성자만 대상으로 허용합니다.
- 알림 OFF 완료 제목에 본문이 중복되던 현상을 수정했습니다.
- 공지의 채팅 이동 버튼이 정보 화면으로 돌아가던 경로를 수정했습니다.
- 나가기 후 뒤로 가면 남아 있던 채팅 경로에서 403이 발생했습니다. 나간 뒤 스택을 커뮤니티+채팅함으로 초기화하고 재검증했습니다.

## 남은 문제와 미검증 범위

1. 웹 채팅 인증 차단: 웹 로그인은 `__TRIO_WEB_SESSION__` 표시와 쿠키 세션을 사용합니다. 채팅 REST/WebSocket은 JWT가 필요합니다. chatToken에서 CHAT_AUTH_REQUIRED로 거절되며 실제 JWT 없이 이 검사를 제거하지 않았습니다. 현재 메인/채팅 API 명세에서 웹 세션용 채팅 티켓·프록시 계약을 찾을 수 없어 백엔드 연계가 필요합니다. 따라서 웹에서 양방향 메시지 수신, 읽음 배지 감소, 작성자 공지 등록·수정은 실행 검증하지 못했습니다.
2. 개발 API에서 간헐적인 502 HTML 오류가 앱 개발 배너에 나타났습니다. 배너가 하단 탭·입력창을 가리는 상황도 확인했습니다. 최종 주요 흐름은 재시도 후 수행했지만 502의 서버 측 원인은 이 UI 테스트로 확정할 수 없습니다.
3. 일부 상대 프로필 조회는 실패해 작성자가 “사용자 2026”으로 표시됩니다. 본인 프로필은 Rururu로 표시됩니다. 상대 프로필 API 응답/동기화 점검이 필요합니다.
4. 재입장 경로는 처음에 조회 오류 문구와 “단체방 다시 입장” 버튼이 함께 나타나고, 버튼을 누르면 정상 입장합니다. 자동 재입장으로 바꾸지는 않았습니다.
5. 카메라 촬영은 시뮬레이터 한계로 미검증. 글 사진 최대 5장 경계, 20명 이상 관리 페이지, 오프라인 장시간 재연결, 토큰 만료, 동시 마지막 자리 경쟁, 서버 장애 복구/관리자 outbox 재실행, 푸시 실제 수신은 미검증입니다. 실제 기기·추가 계정/환경이 필요한 범위입니다.
6. 웹 기존 CommunityDetail/TouchableWithoutFeedback에서 React 19 element.ref 경고가 발생하지만 댓글 작성·수정은 성공했습니다. 공용 컴포넌트는 변경하지 않았습니다.
